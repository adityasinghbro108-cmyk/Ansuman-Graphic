# Render deployment

The Render Blueprint in `render.yaml` installs `requirements.txt` and starts the existing Flask WSGI object with Gunicorn on Render's assigned `$PORT`. Render generates `FLASK_SECRET_KEY`; do not replace it with a value committed to this repository. Locally, `python app.py` continues to use Flask's development server on `127.0.0.1:5000` by default. Set `PORT` to override the local port. `FLASK_DEBUG=1` enables local debugging only; it is ignored on Render.

## Filesystem persistence

The application currently stores its SQLite database at `database/ansuman_graphic.sqlite3`, customer design uploads in `uploads/`, and admin product images/models below `static/`. These paths are on the service filesystem. Render Free web services have an ephemeral filesystem, so database edits, new orders, customer uploads, admin product images, and uploaded models can be lost when the service is replaced or redeployed. The checked-in database and static assets are part of the deployed source, but changes written to those copies are not durable.

`ANSUMAN_DATABASE_PATH` and `ANSUMAN_UPLOAD_DIR` can point SQLite and customer uploads at mounted persistent storage on a plan that provides it. No disk is declared in `render.yaml`, and these overrides do not make Render Free storage persistent. Admin product images/models still use the repository's `static/` tree. For durable production records and uploads on Free, move SQLite to a managed database and customer/admin uploads to persistent object storage; that integration is not included here.

## Customer design files and print exports

When a design is added to the cart, each original image is saved unchanged under `ANSUMAN_UPLOAD_DIR` with a random server filename. Browser preview URLs are not used as stored artwork. Originals stay separate from the print export. A cart item stores a structured design snapshot with the product and selected variant, color, studio view, print areas, per-layer order, source file references, dimensions, scale, rotation, normalized position, and text-layer properties. Checkout copies that snapshot into the order's `items_json` and associates the design and image references with the order and customer. Later cart or studio edits do not rewrite that order snapshot.

The admin order detail page uses order-scoped, admin-only download routes for source images. The Design & Print Center renders one transparent PNG per populated print area and saved product view from the original files and saved layer transforms; text is redrawn from its editable properties. It does not export a screenshot of the 3D mockup. Print PNGs are generated on demand, so they can be regenerated from the order snapshot and originals without replacing either. Current printable-area presets live in `print_artwork.py`: standard areas use 300 DPI and the banner preset uses 150 DPI. New custom products use a 12 × 12 inch, 300 DPI front-area default. Update dimensions and resolutions to match a shop's production specifications before using the files for commercial printing. Missing required source images are reported and prevent export; editable text can be redrawn from its saved properties.

Customer originals and order snapshots reside on the configured application filesystem/database. They are not public static assets. Configure persistent storage for `ANSUMAN_UPLOAD_DIR` and the database in production; otherwise a service replacement can remove both customer originals and the ability to regenerate print files. Admin product photos and models remain in the existing `static/` storage workflow.

## Environment variables

- `FLASK_SECRET_KEY`: generated by `render.yaml`; required when `RENDER=true`.
- `PORT`: set by Render and consumed by Gunicorn automatically.
- `ANSUMAN_DATABASE_PATH`: optional database file path for a persistent mounted volume.
- `ANSUMAN_UPLOAD_DIR`: optional customer-upload directory for a persistent mounted volume.
- `COOKIE_SECURE`: optional override; secure cookies default on Render and off locally.
- `OPENAI_API_KEY`: optional; required only for the live Design Assistant.
- `MAIL_SERVER`, `MAIL_PORT`, `MAIL_USERNAME`, `MAIL_PASSWORD`, `MAIL_DEFAULT_SENDER`, `MAIL_USE_TLS`: SMTP settings for admin password reset email. Configure them in Render's environment; the names are consumed directly by the app and the SMTP password must remain a secret.

Admin recovery creates an additive `admin_recovery_limits` table in the configured SQLite database. Requests are limited to 5 per source address per 15 minutes and 3 per email identity per 15 minutes. Token exchanges are limited to 10 per source address per hour and 5 per token per hour; password submissions are limited to 10 per source address per hour. Recovery link tokens are sent in the URL fragment, which browsers do not include in HTTP requests or access logs. The page submits the token in a CSRF-protected POST, then removes it from the visible URL. Reset links expire after 15 minutes and can be used once.

On Render Free, this flow requires the service to be reading the same SQLite database that contains the admin account. Free service filesystems are ephemeral and no persistent disk is configured here, so database records (including customers, orders, products, admin accounts, and recovery limits) may disappear when the service is replaced or redeployed. This recovery code does not migrate, reset, or recreate the database. Verify the live data location and persistence before deployment; reliable production records require persistent external storage or a managed database.
